# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Cued is a static marketing site for an AI fitness coaching product delivered via text message. It is deployed via GitHub Pages (CNAME: the site domain) from `main`. There is no build system, bundler, or package manager — all code is vanilla HTML/CSS/JS served directly.

## Serving Locally

Open any HTML file directly in a browser, or use a simple static server:

```bash
python3 -m http.server 8080
# or
npx serve .
```

## Tests

`tests/` is the one place with a dependency: tier-1 DOM tests for the interactive pages, run with Node's built-in runner against jsdom with the backend stubbed in-memory (`tests/harness.mjs`). The site itself still has no build step.

```bash
cd tests && npm install && npm test
```

Red-first for behaviour changes to `card.html` (gestures, rendering, API calls); green guards for what already works. The three sign-up suites (`live_signup`, `analytics_events`, `signup_training_time`) loop over `PAGES` and run every test against both `index.html` and `demo-site/index.html` — the two pages carry the same chat and must keep passing together.

## Architecture

The site is entirely self-contained vanilla HTML/CSS/JS with no framework or build step. All CSS is inlined in `<style>` tags; all JS is inlined in `<script>` tags at the bottom of each page.

- **`index.html`** — Main landing page. The entire page is one iMessage thread seen from Cued's side of the screen: Cued is blue (`#007AFF`) and right-aligned; the user is gray and left-aligned. No phone mockup, no device chrome — except the flat vector phone frame in the hero's opening convergence sequence, which is destroyed on its way out. Full design/motion spec lives at `.context/redesign-spec.md` (gitignored — Conductor workspace collateral).
- **`demo-site/index.html`** — The Nov 2026 redesign, served at cued.fit/demo-site while the root page stays the live design (same convention as the old `55/` preview). Self-contained like every page, with root-absolute `/images/…`, `/assets/…`, `/privacy.html` links because it lives one level down; `noindex`; the same Umami tag and sign-up funnel events as the root page. Its design system is documented in its own section below. When it's promoted, it replaces `index.html` at the root (and the links can go relative again).
- **`how-it-works.html`** — Feature explainer page (dark theme, previous design generation).
- **`discover.html`** — Supplementary feature/discovery page (previous generation).
- **`profile.html`** — The per-user profile page. The coach texts each user a link `profile.html?t=<token>` at kickoff (backend `profile_page.py`); the page fetches `GET /profile/<token>` from the Railway backend and renders it read-only in the current Messages design (Cued's blue bubbles, hairline rows, serif headers, light/dark tokens mirrored from `index.html`) across five hash-linked tabs — today, you (incl. a bodyweight line), training (lift-progress line + consistency strip + "my workouts" opening on today's session), nutrition (calorie/protein rings vs. target, 14-day strip, "my meals"), memory. Charts are inline SVG, one series, brand blue; the series math (lift top sets, weekly counts, daily macros) is computed by the backend's `profile_page.py`, not the page. No token or the old `?phone=` link shows a "text Cued for your link" state. Nothing is stored in the browser; edits happen by texting Cued.
- **`welcome.html`** — Post-signup confirmation page (dark theme, previous generation).
- **`privacy.html`** / **`terms.html`** — Legal pages (dark theme, previous generation; accent updated to the current brand blue).
- **`index2.html`**, **`testing/index.html`**, **`css/funnel.css`**, **`js/funnel.js`** — Legacy artifacts from earlier design generations. Nothing references them; safe to ignore.

**Analytics** — every live page (`index`, `profile`, `card`, `privacy`, `terms`, `how-it-works`, `discover`) loads the Umami Cloud tracker (`cloud.umami.is/script.js`, one `data-website-id` for all of cued.fit) just before `</head>`; the free Hobby plan (100K events/month, 1 website, 6 months retention). Cookieless page views, visits, referrers, UTM campaigns, country, device/browser. `index.html`'s sign-up card fires the site's only custom events through a guarded `track()` helper that no-ops when `window.umami` is absent (blocked, offline, jsdom): `signup-open {source}` when a chat starts, `signup-step {step, name, source}` each time the progress bar advances (names in `STEP_NAMES`), `signup-submit {result: live | live-exists | waitlist | waitlist-exists | rejected | error, source}`, and `signup-imessage` / `signup-sms {source}` for the success-screen taps. Printed QR codes and shared links carry `?src=<label>` (or `utm_source`): the page fires one `qr-scan {src}` on landing (retrying briefly for the deferred tracker) and adds `ref: <label>` to every funnel event, so flyer scans can be followed into sign-ups; the label is slugged (lowercase, `a-z0-9_-`, ≤50 chars) and lives in a variable only. Never put a typed answer, name, phone or email in an event — `privacy.html`'s "Website Analytics" section promises that and must stay true. `tests/analytics_events.test.mjs` stubs the tracker and asserts the sequence through a full chat.

**External dependencies loaded via CDN (no local install):**
- Google Fonts on `index.html`: Hedvig Letters Serif (section headers), Inter 400/500 (bubble text), Outfit (wordmark only). The nav brand is `images/cued-logo.svg` (circle-and-dot mark) plus a blue "cued" wordmark.

## index.html Design System

**Tokens** — `--blue: #007AFF` (Apple iMessage system blue; the brand blue globally), `--blue-deep` `#0062CC` (hover), `--blue-soft` `#E5F1FF` (tints/focus), `--gray` `#E9E9EB` (user bubbles), flat white `--bg`, `--poll-fill`/`--poll-ink` (iOS 26 Messages poll orange). The bubbles are the only color on the page — no gradients, no drop shadows, no hover states on bubbles, no second accent beyond the poll orange.

**Dark mode** — a small sun/moon button fixed in the bottom-right corner (`.mode-btn`/`#modeBtn`, desktop only; moon in light mode, sun in dark) toggles `html.dark`, which overrides the tokens to real Messages dark (true-black `--bg`, `#3B3B3D` user bubbles, `#0A84FF` iOS dark system blue, dark poll orange). All theme-dependent colors live in tokens on `:root`/`html.dark` — never hardcode a color in a rule; add a token. The choice persists in `localStorage('cued-theme')` and is applied pre-paint by the head script to avoid a white flash.

**Desktop scrollytelling (≥768px, motion OK)** — the hero lands on a serif headline ("Meet cued. made for your college life." + subhead "Your personal fitness coach — no app, just texts [Messages icon] / Your cue to lock in." + a "Join the waitlist" CTA (`#heroCtaTop`, source `hero`), `.hero-head`), the Campanile fully drawn at left, and a flat vector iPhone frame (`.cv-phone`: evenodd bezel ring, island, side buttons in `--cv-bezel`; a Messages-style header with the cue-ball avatar and "cued" on the screen paper in `.cv-under`) peeking up from the bottom edge (offset `PEEK` × height, pushed down further if the headline block would collide) with the first bubble already on its screen; the remaining bubbles pop on a timeline at the first scroll gesture or after ~2s idle. The headline inks in word by word on load (JS wraps words in `.w`, staggered `transition-delay`, `.inked` after fonts) and the subhead carries an inline Messages icon. Ten app icons (`images/app-icons/`: MyFitnessPal, MacroFactor ×2, Hevy, MyNetDiary, Reminders, Notes, pen-and-paper, Google Calendar, Canvas) are scattered around the headline and phone from the first frame like stickers (`SLOTS`, tilted, gently bobbing, still). The hero thread itself is what's on the phone: the driver scales `#hero .shell` about its bottom-right corner and parks it inside the drawn frame (no copy of the bubbles). The hero's first `--cv-len` (300vh) of scroll is the scrubbed convergence sequence, a pure function of progress `p` written once per frame from one IntersectionObserver-gated rAF loop, transform + opacity only: headline drifts up and out (p .05–.18) → phone rises from its peek to center (.08–.30) while the icons glide from their slots onto the orbit ellipse (.08–.28) and the orbit starts turning (angle accumulates only while p is in .08–.24, ~40s per revolution) → icons stream into the phone in index order (.32–.56) → absorb pulse + faint blue screen wash (.56–.62) → the phone, its thread, and the Campanile fade out (.62–.70) → the statement (`.hero-say`, a few short sentences in the site's voice with the app icons inline as tile clusters, `text-wrap:balance`; each cluster follows a verb — "knows your classes" for connected accounts, "replaces your lift … and meal … apps" for retired ones — plus "nothing to download", because without the verbs readers took the icons for apps they'd need to install) fades up (.66–.74) and inks in word by word (.70–.98; JS wraps words and clusters in `.sw`, toggles `.on`; un-inked icons are grayscale). After `p = 1` the hero holds 20vh on the inked statement (set a little below center), then the stage releases and the tour starts on its own screen after a short breath — the statement and the first conversation never share a frame. A load or fling already past the hero settles it instantly. No icon labels in the scatter; Strava is deliberately absent (§7 "keep strava"). The floating waitlist pill doubles as the hero CTA — it surfaces bottom-center once the bubbles have settled and the sequence has played out (`cvPast`); the scroll cue is flow-only (the peeking phone is the cue in the pin).

Below the hero, the tour is a plain vertical flow (`.sec--pin` is now just a hook name): no sticky stages, no pinning, no push-up — a Messages-width column (`.sec--pin .shell` ≤760px, ~20px bubbles, 72% max bubble width), small inline serif headers (`.hdr-flow`, ~26px; mid-thread headers carry a top margin), bubbles fading in via IntersectionObserver as they scroll into view, section rhythm from `.sec--pin{padding-top}`. Compressed 2026-10-05 from eight sections to five so the tour scrolls ~30% shorter: "i know your week" (texts first + calendar + poll), "i log your sets" (checklist + PR + workout card), "i know what's for dinner" (dining-hall pick + plate photo), "i remember → and i read your watch" (midterm callback + chart + short-night move + no-watch line), "it stays between us" (the privacy beat — every bubble is a promise `privacy.html` backs; keep them in sync). The poll auto-picks and the checklist logs itself on intersection. The `.sec-h` pinned-header markup is still in the DOM but hidden.

**Mobile (<768px, any motion preference)** — the same flow tour; only sizing differs (tight shell, 17px bubble text — real Messages size, 27px inline headers, compact close section). The hero is a static scene, not a scrub (`MOBILE HERO SCENE` block at the end of the sheet): the stage becomes a three-row grid — headline + subhead (the in-flow `.hero-ctas` row is hidden; the mobile CTA is a full-width "Join the waitlist" button pinned to the bottom of the screen, `.m-cta` / `#heroCta`, source `hero`, over a short page-color fade, visible from the first frame through the tour and yielding once the close section is in view), then one cell where the faint Campanile, the phone paper (`.cv-under`), the thread (`.shell`, absolutely placed on the phone's screen between header and composer at 13.5px) and the bezel + six sticker icons (`.cv`, fixed `nth-child` slots, 3/5/6/8 hidden) overlap, then the statement at a smaller size. Bubbles pop in on the screen via the hero timeline (transform killed). The nav's "get started" and the corner dark-mode button are hidden on mobile; the floating pill and scroll cue are desktop-only (the pinned bar replaces them). A notification banner (`.notif`, motion only — iOS-style top banner on mobile, macOS-style top-right card on desktop) nudges the reader to scroll once they've dwelt on the hero ~2.6s past the hero CTA beat; the dwell is a watcher, not a one-shot — leaving the hero resets it, returning re-arms it — and it fires at most once, never after a waitlist CTA touch. It auto-dismisses after ~6.4s, and on tap scrolls to the first section.

**`prefers-reduced-motion` (any width)** — on desktop the hero joins the flow (no sticky, no convergence: headline in flow above the drawing band, then the bubbles, then the inked statement); on phones it's the same static scene as motion-OK mobile; every transition is off. It keeps the width-driven sizing (desktop shell and bubble scale ≥768px, mobile sizing below) — reduced motion changes how the page moves, never how wide it is. Windows "Animation effects: off" reports this query, so a real share of desktop visitors land here; never let it collapse into a phone column. Mode is switched live on media-query change in JS.

**No scroll snap** — a mandatory section snap was tried (in the earlier pinned-tour design) and it traps mouse-wheel readers (nearly every Windows visitor). Verify wheel scrolling (100px notches) and reduced-motion at desktop widths in headless Chromium before shipping scroll-machinery changes.

**Close (`#signup`)** — the statement's twin: one serif line (`.close-say`, rides `.say`) "your cue to lock in." that inks in word by word on intersection, a small gray subline "nothing to download. ready when you are." (`.close-sub`) (JS wraps words in `.sw`, staggered timers; reduced motion renders inked), then the pill CTA (`#closeCta`, source `close`). No bubble. Full-height centered on desktop, compact with a full-width button on mobile.

**Sign-up chat (historically "the waitlist")** — every CTA reads "text cued" (live sign-ups since 2026-10-15; the ids/function names keep the waitlist wording) and calls `window.openWaitlist(source)`, which opens a Messages-style card (`.co-*` rules at the end of the sheet; tokens mapped from the page's so dark mode is free) running the same conversational sign-up as the legacy pages' `legacy/js/signup.js`, tightened 2026-09-19 to be minimal and quick: ten steps, one lowercase bubble each in the coach's texting voice, ~320ms typing pill. The composer (field + send arrow) is the same slim row on every step; questions with fixed answers are answered from a list bubble cued sends right after the question (`.co-msg.co-opts`: one gray received bubble, rows stacked with hairlines, a ring at the right that fills blue with a check — the tour poll's ring in the thread's palette; no pills, nothing scrolls sideways, every option visible). A single-select row sends itself; multi-select rows toggle, the read-only field mirrors the running answer, the arrow sends. The bubble then locks (`.done`: picks stay checked, the rest dim) and the answer follows as the reader's blue bubble. No grids, no chips, no confirm buttons. Only name (asked as "what's your full name?"; the coach greets by first name, and the payload sends `name` = first name — what the backend's hook template and prompts inject — plus `full_name` for the admin side only), age, phone and email are typed (the phone formats itself as `(510) 555-1234` and must be a 10-digit US number before it's accepted; the email is optional and says so — "totally optional" in the bubble, `(optional)` in the placeholder, a `skip` button in the composer row (an empty send skips too, echoed as the reader's "skip" bubble) — and when given must look like one, re-asked otherwise, lowercased; the backend validates it again). Consent is cued's fine-print bubble (`.co-msg.fine`, terms + privacy links inline) answered with the one chip on offer, "i agree", which sends as the reader's bubble. A 2px blue hairline under the header (`.co-progress`) fills a step at a time; "Delivered" (`.co-meta`) sits under the reader's latest bubble; earlier bubbles fade out under the header (mask) instead of clipping. It is literally the reader's phone, so their sends are blue on the right and Cued's replies gray on the left — the one place the page's Cued-is-blue convention flips. The sheet is frosted glass (`--co-glass`, translucent over a 28px backdrop blur with a hairline rim; inputs/chips sit on `--co-field`, also translucent), so its bubble tails are NOT the page's two-pseudo-element carve (a card-colored carve would sit as an opaque notch on glass): one color extension per bubble, shaped by a `mask` that keeps the in-bubble part plus the curved tip. Sizing never needs a scroll to see the whole thing: desktop is a fixed card `min(560px, 100% - 48px)`; under 768px it's a bottom sheet at `calc(100% - 40px)` of an overlay whose height/top (and width/left) the script sets from `window.visualViewport` while open, so an open keyboard shrinks the sheet instead of covering the compose row and a zoomed page still shows the whole sheet. Every input must compute to 16px on phones — the rule has to be `.co-bg .co-input` to outrank `.co-bg input{font:inherit}`, or iOS zooms 16/15 on focus, never zooms back, and the sheet runs off the right edge (verified at 320×568 up to 412×915 and a 390×430 keyboard-sized viewport). On consent it POSTs `{ name, full_name, phone, email, source, ts, timezone, active: false, status: 'waitlist', age, gender, goal: [...], biggest_obstacle, experience, equipment, sms_consent: true }` to the Railway `/waitlist` endpoint (the route name is historical). Since 2026-10-15 (backend `LIVE_SIGNUPS_ENABLED`) the backend creates a LIVE account, provisions the Photon iMessage line and returns `imessage_link`, `live: true` and `hook_deferred`: with a link the coach's first text waits for the reader's one tap — the success screen says "you're in" and offers "text me on iMessage" (opens Messages pre-addressed with "hey cued"; their send gets the coach's first text back, blue) and "i don't have an iPhone" (`POST /signup/channel { phone, channel: 'sms' }` → the first text by SMS right away); no link → "just texted you". A response without `live` is an older backend still running the waitlist (pending row, one holding line until an admin activates) and gets the 2026-09-19 copy ("you're on the list" / "the second your spot opens") so the two deploys can land in either order. Re-opening the card resumes the chat where it was left. Never run the flow against the real backend in tests — `tests/live_signup.test.mjs` and `tests/signup_training_time.test.mjs` walk the chat in jsdom with `fetch` stubbed.

**Bubble anatomy** — tails only on the last bubble of a run, built from two pseudo-elements (color extension + page-white carve); both must be at least as tall as the corner radius or the tail detaches. The poll's width is matched to the widest sibling bubble by JS. Every auto-play reveal (hero and tour, motion OK) gets a ~500ms three-dot typing lead-in: a JS-injected `.typing` pill per thread, absolutely positioned just under the last revealed bubble on the incoming bubble's side (blue for Cued, gray for the user), lifting the thread by its height while it shows; the arriving bubble replaces it. The hero's first pop after a scroll start skips it (no room before the reveal).

## demo-site/index.html Design System (the Nov 2026 redesign)

(Everything in this section describes `demo-site/index.html`. The root `index.html` is the previous generation, documented above.)

**Structure** — one `<section>` per beat, full-bleed backgrounds alternating the two creams (`--cream #F5EAE0` / `--cream-2 #FBF6F1` — the page went fully warm 2026-11-14; nothing is white except cards and app tiles), 1200px `.wrap`, 24px side padding (64px from 1024px). In order: `#hero` (cream) → `#say` (strip, cream-2) → `#proof` (pinned chat, cream) → `#apps` (cream-2) → `#privacy` (cream) → `#berkeley` (cream-2) → `#signup` (close, cream) → `#faq` (cream-2) → footer. Seams are soft (tomo.ai reference): `section.blend` fades in from `--from` (the previous section's color) over a `::before` band, `section.blend-to` fades out into `--to`; sections `isolation:isolate` so the band sits under content. Lowercase everywhere; exactly one emoji on the page (🎉 on the PR bubble). No floating or drifting elements.

**Tokens** — `--blue #006EFD`, `--blue-hover #0052BD` (the spec calls this `--blue-ink`, but that name means "text on blue" to the sign-up card, so hover is `--blue-hover`/`--blue-deep`), `--black`, `--gray-bubble #ECE7E1` (iMessage gray warmed for cream), `--gray-text`, `--cream` / `--cream-2` (the page surfaces; `--bg` defaults to cream-2; `--tint-1`/`--tint-2` still exist but resolve to the creams), `--line #E8DCCF` warm hairlines, `--fill #EFE3D7` warm fills, `--card #FFFFFF` (cards, app tiles, the privacy thread card, the chat header pill), poll orange kept. Aliases (`--ink`, `--field`, `--gray`, `--f-msg`, `--f-header`…) exist only because the sign-up card (`.co-*`) reads them. Dark mode maps the creams to warm near-blacks. Tinted sections set `--bg` locally so bubble tails carve the right color.

**Bubbles** — `.thread` > `.msg.coach` / `.msg.user` (+ `.t` tail on the last bubble of a run, `.turn` for a sender change). Inside the phone the convention is the standard screen-recording one: coach GRAY LEFT, user BLUE RIGHT. Colors are `--bubble-coach` / `--bubble-user`; sides come from the thread — add `.flip` to a `.thread` to mirror it (the one-change revert). Poll (`.poll` > `.poll-row`, `.pick`/`.chosen`), checklist (`.checklist`, `.done`), chart bubble (`.msg.chart`, bars in brand blue on gray), photo bubble (`.msg.photo`), workout card (`.msg.card`) are the previous generation's components, restyled.

**Thread engine** (`playThread` in the script) — a `.thread[data-play]` starts with its bubbles hidden (gated on `html.js`); playing reveals them in order with a 520ms three-dot typing pill on the incoming side and a bottom-anchored push-up (the thread sits translated down by the unrevealed height). Polls auto-pick after 800ms unless clicked; checklist rows 1–2 self-check, the "swapped it in" bubble rewrites row 3 to 190 × 4 and checks 3–4. Reduced motion reveals everything at once. Threads outside the pinned phone play on intersection; a thread plays once.

**Hero** — two columns on cream (founder reference, 2026-11-14): `#hero.cream` (`--cream #F3E7DC`, sampled from the video's backdrop; warm near-black in dark mode) with `.hero-grid` (1.5fr / 1fr, 24–44px gap, stacked under 1024px). Left, `.hero-copy`, left-aligned: "meet cued" as a small kicker (`.hero-h .kicker`, .5em) over "the coach that" + a rotating phrase in brand blue (`.rot` > `.rot-item`: "lives in your texts." / "replaces [six retired-app icons]" / "builds your workouts." / "tracks your food." / "knows the college life." / "knows your schedule."; JS cycles every 2.6s with a fade-up, sizes the slot to the tallest phrase so nothing below moves, pauses off-screen, static under reduced motion; an `.sr-only` "lives in your texts." keeps the h1 readable) at `clamp(38px,4.4vw,60px)` — capped so every phrase stays ONE line in the ~617px column at 1440 (measured at 1440/1280/1100/1024; a two-line phrase would leave a gap under the one-liners), 34px on phones; then the one-sentence Outfit sub-line ("it knows your classes, replaces your lift and meal apps, and texts first. nothing to download."), one `text cued` button (`#heroCtaTop`, `.btn.sq` — 50px tall, 14px corners, the squarish shape kept from the retired chatbox). (The "free during beta · made in berkeley" caption was removed 2026-11-14.) Right, `.hero-video`: a rounded 4:3 card (16:11 stacked) cropping the founder's locked-off mascot clips — `assets/hero/cued-hero.mp4` (8s) and `cued-hero-2.mp4` (7s), both 1280×720 on the same cream, stacked `<video>`s the script plays back to back with a 0.6s opacity crossfade (`.on`) that starts 1s before the outgoing clip's end so it never reaches `ended`, forever; muted/playsinline, poster `cued-hero-poster.jpg` = clip 1's first frame; clip 1 keeps `autoplay loop` as the no-JS fallback (the script drops `loop` when it takes over). Paused off screen; poster only under reduced motion. Add a clip = add a `<video>`; the handoff is generic. The live avatar (`.cued-avatar`) is no longer in this hero (the video is the mascot); it still lives on `index-b.html`. No Campanile in the hero. The block fades in over 400ms on load.
