# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Cued is a static marketing site for an AI fitness coaching product delivered via text message. It is deployed via GitHub Pages (CNAME: the site domain) from `main`. There is no build system, bundler, or package manager — all code is vanilla HTML/CSS/JS served directly.

## Serving Locally

Open any HTML file directly in a browser, or use a simple static server:

```bash
python3 -m http.server 8080
# or
npx serve .
```

## Tests

`tests/` is the one place with a dependency: tier-1 DOM tests for the interactive pages, run with Node's built-in runner against jsdom with the backend stubbed in-memory (`tests/harness.mjs`). The site itself still has no build step.

```bash
cd tests && npm install && npm test
```

Red-first for behaviour changes to `card.html` (gestures, rendering, API calls); green guards for what already works.

## Architecture

The site is entirely self-contained vanilla HTML/CSS/JS with no framework or build step. All CSS is inlined in `<style>` tags; all JS is inlined in `<script>` tags at the bottom of each page.

- **`index.html`** — Main landing page, rebuilt 2026-11-08 to the "cued.fit v2" spec (one hero, a pinned-phone proof section, mascot in three places). See the design-system section below.
- **`index-b.html`** — Variant B of the landing page (2026-11-08): identical except the hero, where the live avatar sits inline in the headline ("meet cued [avatar], / the coach that / [rotating phrase]", muse.ai-style) instead of above a kicker. Keep in sync with `index.html` by hand; not covered by the tests.
- **`how-it-works.html`** — Feature explainer page (dark theme, previous design generation).
- **`discover.html`** — Supplementary feature/discovery page (previous generation).
- **`profile.html`** — The per-user profile page. The coach texts each user a link `profile.html?t=<token>` at kickoff (backend `profile_page.py`); the page fetches `GET /profile/<token>` from the Railway backend and renders it read-only in the current Messages design (Cued's blue bubbles, hairline rows, serif headers, light/dark tokens mirrored from `index.html`) across five hash-linked tabs — today, you (incl. a bodyweight line), training (lift-progress line + consistency strip + "my workouts" opening on today's session), nutrition (calorie/protein rings vs. target, 14-day strip, "my meals"), memory. Charts are inline SVG, one series, brand blue; the series math (lift top sets, weekly counts, daily macros) is computed by the backend's `profile_page.py`, not the page. No token or the old `?phone=` link shows a "text Cued for your link" state. Nothing is stored in the browser; edits happen by texting Cued.
- **`welcome.html`** — Post-signup confirmation page (dark theme, previous generation).
- **`privacy.html`** / **`terms.html`** — Legal pages (dark theme, previous generation; accent updated to the current brand blue).
- **`index2.html`**, **`testing/index.html`**, **`css/funnel.css`**, **`js/funnel.js`** — Legacy artifacts from earlier design generations. Nothing references them; safe to ignore.

**External dependencies loaded via CDN (no local install):**
- Google Fonts on `index.html`: Hedvig Letters Serif 400 (every headline), Outfit 300/400/500 (wordmark, nav, buttons, captions, FAQ). Everything inside the phone uses the system stack (`-apple-system, "SF Pro Text", …`). No other fonts.

## index.html Design System (v2, 2026-11-08)

**Structure** — one `<section>` per beat, full-bleed backgrounds alternating the two creams (`--cream #F5EAE0` / `--cream-2 #FBF6F1` — the page went fully warm 2026-11-14; nothing is white except cards and app tiles), 1200px `.wrap`, 24px side padding (64px from 1024px). In order: `#hero` (cream) → `#say` (strip, cream-2) → `#proof` (pinned chat, cream) → `#apps` (cream-2) → `#privacy` (cream) → `#berkeley` (cream-2) → `#signup` (close, cream) → `#faq` (cream-2) → footer. Seams are soft (tomo.ai reference): `section.blend` fades in from `--from` (the previous section's color) over a `::before` band, `section.blend-to` fades out into `--to`; sections `isolation:isolate` so the band sits under content. Lowercase everywhere; exactly one emoji on the page (🎉 on the PR bubble). No floating or drifting elements.

**Tokens** — `--blue #006EFD`, `--blue-hover #0052BD` (the spec calls this `--blue-ink`, but that name means "text on blue" to the sign-up card, so hover is `--blue-hover`/`--blue-deep`), `--black`, `--gray-bubble #ECE7E1` (iMessage gray warmed for cream), `--gray-text`, `--cream` / `--cream-2` (the page surfaces; `--bg` defaults to cream-2; `--tint-1`/`--tint-2` still exist but resolve to the creams), `--line #E8DCCF` warm hairlines, `--fill #EFE3D7` warm fills, `--card #FFFFFF` (cards, app tiles, the privacy thread card, the chat header pill), poll orange kept. Aliases (`--ink`, `--field`, `--gray`, `--f-msg`, `--f-header`…) exist only because the sign-up card (`.co-*`) reads them. Dark mode maps the creams to warm near-blacks. Tinted sections set `--bg` locally so bubble tails carve the right color.

**Bubbles** — `.thread` > `.msg.coach` / `.msg.user` (+ `.t` tail on the last bubble of a run, `.turn` for a sender change). Inside the phone the convention is the standard screen-recording one: coach GRAY LEFT, user BLUE RIGHT. Colors are `--bubble-coach` / `--bubble-user`; sides come from the thread — add `.flip` to a `.thread` to mirror it (the one-change revert). Poll (`.poll` > `.poll-row`, `.pick`/`.chosen`), checklist (`.checklist`, `.done`), chart bubble (`.msg.chart`, bars in brand blue on gray), photo bubble (`.msg.photo`), workout card (`.msg.card`) are the previous generation's components, restyled.

**Thread engine** (`playThread` in the script) — a `.thread[data-play]` starts with its bubbles hidden (gated on `html.js`); playing reveals them in order with a 520ms three-dot typing pill on the incoming side and a bottom-anchored push-up (the thread sits translated down by the unrevealed height). Polls auto-pick after 800ms unless clicked; checklist rows 1–2 self-check, the "swapped it in" bubble rewrites row 3 to 190 × 4 and checks 3–4. Reduced motion reveals everything at once. Threads outside the pinned phone play on intersection; a thread plays once.

**Hero** — two columns on cream (founder reference, 2026-11-14): `#hero.cream` (`--cream #F3E7DC`, sampled from the video's backdrop; warm near-black in dark mode) with `.hero-grid` (1.5fr / 1fr, 24–44px gap, stacked under 1024px). Left, `.hero-copy`, left-aligned: "meet cued" as a small kicker (`.hero-h .kicker`, .5em) over "the coach that" + a rotating phrase in brand blue (`.rot` > `.rot-item`: "lives in your texts." / "replaces [six retired-app icons]" / "builds your workouts." / "tracks your food." / "knows the college life." / "knows your schedule."; JS cycles every 2.6s with a fade-up, sizes the slot to the tallest phrase so nothing below moves, pauses off-screen, static under reduced motion; an `.sr-only` "lives in your texts." keeps the h1 readable) at `clamp(38px,4.4vw,60px)` — capped so every phrase stays ONE line in the ~617px column at 1440 (measured at 1440/1280/1100/1024; a two-line phrase would leave a gap under the one-liners), 34px on phones; then the one-sentence Outfit sub-line ("it knows your classes, replaces your lift and meal apps, and texts first. nothing to download."), one `text cued` button (`#heroCtaTop`, `.btn.sq` — 50px tall, 14px corners, the squarish shape kept from the retired chatbox). (The "free during beta · made in berkeley" caption was removed 2026-11-14.) Right, `.hero-video`: a rounded 4:3 card (16:11 stacked) cropping the founder's locked-off mascot clips — `assets/hero/cued-hero.mp4` (8s) and `cued-hero-2.mp4` (7s), both 1280×720 on the same cream, stacked `<video>`s the script plays back to back with a 0.6s opacity crossfade (`.on`) that starts 1s before the outgoing clip's end so it never reaches `ended`, forever; muted/playsinline, poster `cued-hero-poster.jpg` = clip 1's first frame; clip 1 keeps `autoplay loop` as the no-JS fallback (the script drops `loop` when it takes over). Paused off screen; poster only under reduced motion. Add a clip = add a `<video>`; the handoff is generic. The mp4 is deliberately NOT under the LFS pattern (`videos/*.mp4`): GitHub Pages serves LFS pointers, not files. The live avatar (`.cued-avatar`) is no longer in this hero (the video is the mascot); it still lives on `index-b.html`. No Campanile in the hero. The block fades in over 400ms on load.

**"say anything." strip** (`#say`) — two rows of blue user bubbles scrolling in opposite directions (CSS keyframes, 40s, duplicated content, pause on hover, `aria-hidden` with an `.sr-only` list). Rows are built by JS from `#mqList`. Static under reduced motion.

**Proof** (`#proof`) — the markup is the stacked form: five `article.step` blocks (copy + its own phone markup + thread, `data-status` for the header pill). At ≥1024px with motion OK, `pinProof()` builds a 500vh `.proof-track` with a sticky 100vh grid: left column = the five `.step-copy` blocks (only the active one displayed) + the per-step mascot render (the stepper list is still built and marked by `setStep` but no longer appended — removed 2026-11-14) in the bottom-left corner (`.proof-mascot`, see **Mascot**); right = ONE chat (step 1's header cloned, every thread moved into its `.screen`). Scroll progress picks the band (`floor(p*5)`), swaps the active thread, stepper row and status pill, and plays the thread on first entry. `unpinProof()` moves everything back; switched live on media-query change. Since 2026-11-14 (founder reference) the phone slab is gone and the whole section sits on the hero's cream: the `.phone`/`.phone-screen` markup is kept for the engine but unframed by `#proof` rules (no island/composer/home bar/chevrons; avatar 48px + name + status pill, then the thread in Outfit at 15–16.5px in a 440px column (1fr/1fr grid — shrunk 2026-11-14 so the chat stops competing with the headline), plain rounded bubbles with no tails, 86% max width; `.screen` is a fixed-height, bottom-anchored, overflow-hidden box so the push-up still works). The step sub-lines are hidden (`#proof .step-copy .sub` — fewer words on the left). The `tints` array in the script is all-empty now. Under 1024px and under reduced motion nothing pins: header, then the chat, stacked and centered.

**Apps** (`#apps`) — two labeled rows (plugs into: Google Calendar, bCourses/Canvas, Google Health, Apple Watch, Strava — founder added the last three icons 2026-11-08 (`images/app-icons/google-health.webp`, `apple-watch.webp`, `strava.webp`); replaces: MyFitnessPal, MacroFactor, Hevy, Notes, Reminders, pen & paper). Icon tiles sit on white so transparent icons still read as tiles.

**Privacy / Berkeley / Close / FAQ** — privacy: three facts (+ the lock mascot render under them) beside a 360px `.thread-card`. Berkeley: `.photo-slot` (4:5, takes an `<img>` or a muted `<video>`; the graduation mascot render as the placeholder until there's a founder photo) + first-person founder copy. Close: the dumbbell render (`.mascot`, ~420px square feathered, 240px mobile) over "your cue to lock in." ("cue" in blue), `#closeCta`, the Campanile drawing big and faint (30%) anchored bottom-LEFT, on cream. FAQ: five `<details>`, lowercase header. Footer: flat mark + links + "made in berkeley, for berkeley · © 2026".

**Chrome** — a step rail (`#rail`, ≥1024px) on the left edge appears ONLY while the proof is pinned: `pinProof()` builds one 5px dot per step, `setStep` marks the current one (blue, scaled), hover shows the step headline as a small tag, click scrolls to that band; it fades out when the proof releases (founder: dots only during the sticky section). Nav is transparent everywhere (the `nav.scrolled` class is still toggled past the hero but styles nothing now); brand = the live site's: blue `cued` wordmark (Outfit 400, 22px) followed by the flat circle-and-dot ball, inline SVG with `currentColor` so it matches `--blue` (restored 2026-11-08; the 3D ball in `assets/brand/` is unused). The mascot avatar stays on the phone and the sign-up card; the hero shows the video loop. Floating `text cued` pill (`#floatCta`): opaque blue, 2px white ring, bottom-center 24px; hidden while the hero, the close or the FAQ (and so the footer) is in view and, under 480px, while the pinned proof is active — with no nav button, the pill is the only CTA mid-page. Dark-mode button bottom-right (desktop only) toggles `html.dark` (tints → `#0F131A` / `#121A26`, bubbles keep their colors, the phone slab gets a hairline edge); persisted in `localStorage('cued-theme')`, applied pre-paint.

**Sign-up chat** — unchanged from the previous generation (CSS + JS carried over verbatim; its avatar is now the mascot). Every CTA calls `window.openWaitlist(source)`: `heroCtaTop`, `floatCta`, `closeCta` (the nav button was removed 2026-11-14; the nav is just the brand; the sign-up script's `navCta` lookup is null-safe). The tests in `tests/live_signup.test.mjs` walk it in jsdom with `fetch` stubbed; never run it against the real backend in tests.

**Mascot** — the current character is the founder's 2026-11-14 "marshmallow" set in `assets/mascot/v2/` (nine 1800px JPEG renders on their own cream, stored as 900px WebP + JPEG: `cued-texting`, `-sleep` (pillow), `-whistle`, `-dumbbell` (headband), `-ball`, `-run`, `-bottle`, `-trophy`, `-ball-blank` (faceless, unused), plus `cued-face-256` — a square crop of the ball render's head, used as the round avatar on the phone headers and the sign-up card). The renders are NOT transparent: wherever one sits on the page it's on `--cream` (`#F5EAE0`, sampled from their backdrop) with a soft rectangular `mask-image` (two linear gradients, `mask-composite:intersect`, fading only the outer 9% of each side — a radial mask cut corner props like the dumbbell and PR stars), so never place one on white or a blue tint. Crops must stay INSIDE the render: the backdrops have a vignette, so padding past the edge with flat cream shows a seam. Placements: hero = the two video clips; proof = one render per step in the bottom-left corner of the sticky left column (`.proof-mascot` > five `img`s, `.on` crossfades with the step: `cued-week` calendar wink / `cued-sets` dumbbell + PR + clipboard / `cued-dinner` bowl / `cued-remember` head-tap + chart phone / `cued-watch` — `cued-week`/`-sets`/`-dinner`/`-remember`/`-watch`/`-lock` (privacy, under the facts as `.side-mascot`) are 1100px-wide crops of the founder's full-size square renders (2026-11-14; 462:365 framing, character ~74% of the crop where the render allows, never cropped past the render's edge; `cued-remember` is the wifi-arcs + chart-phone render); `cued-grad` (the berkeley founder slot until there's a photo), `cued-halo` and `cued-chat` (unused) are still the lower-res ~462×365 slices from the two 3×2 contact sheets, re-toned +6/+3/+4; the earlier square renders whistle/trophy/bottle/texting/sleep/ball/run/bottle remain in the folder, unused except `cued-dumbbell` and `cued-face-256`); close = the dumbbell render over "your cue to lock in." (the close moved from `--tint-2` to cream for this). The older headband mascot files (`cued-avatar-*`, `cued-mascot-flex`, `cued-mascot-texting`, `cued-mascot-wave`) are retired on `index.html`; `index-b.html` still uses the live-avatar layers.
