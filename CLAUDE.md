# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Cued is a static marketing site for an AI fitness coaching product delivered via text message. It is deployed via GitHub Pages (CNAME: the site domain) from `main`. There is no build system, bundler, or package manager — all code is vanilla HTML/CSS/JS served directly.

## Serving Locally

Open any HTML file directly in a browser, or use a simple static server:

```bash
python3 -m http.server 8080
# or
npx serve .
```

## Architecture

The site is entirely self-contained vanilla HTML/CSS/JS with no framework or build step. All CSS is inlined in `<style>` tags; all JS is inlined in `<script>` tags at the bottom of each page.

- **`index.html`** — Main landing page. The entire page is one iMessage thread seen from Cued's side of the screen: Cued is blue (`#007AFF`) and right-aligned; the user is gray and left-aligned. No phone mockup, no device chrome — except the flat vector phone frame in the hero's opening convergence sequence, which is destroyed on its way out. Full design/motion spec lives at `.context/redesign-spec.md` (gitignored — Conductor workspace collateral).
- **`how-it-works.html`** — Feature explainer page (dark theme, previous design generation).
- **`discover.html`** — Supplementary feature/discovery page (previous generation).
- **`profile.html`** — The per-user profile page. The coach texts each user a link `profile.html?t=<token>` at kickoff (backend `profile_page.py`); the page fetches `GET /profile/<token>` from the Railway backend and renders it read-only in the current Messages design (Cued's blue bubbles, hairline rows, serif headers, light/dark tokens mirrored from `index.html`) across five hash-linked tabs — today, you (incl. a bodyweight line), training (lift-progress line + consistency strip + "my workouts" opening on today's session), nutrition (calorie/protein rings vs. target, 14-day strip, "my meals"), memory. Charts are inline SVG, one series, brand blue; the series math (lift top sets, weekly counts, daily macros) is computed by the backend's `profile_page.py`, not the page. No token or the old `?phone=` link shows a "text Cued for your link" state. Nothing is stored in the browser; edits happen by texting Cued.
- **`welcome.html`** — Post-signup confirmation page (dark theme, previous generation).
- **`privacy.html`** / **`terms.html`** — Legal pages (dark theme, previous generation; accent updated to the current brand blue).
- **`index2.html`**, **`testing/index.html`**, **`css/funnel.css`**, **`js/funnel.js`** — Legacy artifacts from earlier design generations. Nothing references them; safe to ignore.

**External dependencies loaded via CDN (no local install):**
- Google Fonts on `index.html`: Hedvig Letters Serif (section headers), Inter 400/500 (bubble text), Outfit (wordmark only). The nav brand is `images/cued-logo.svg` (circle-and-dot mark) plus a blue "cued" wordmark.

## index.html Design System

**Tokens** — `--blue: #007AFF` (Apple iMessage system blue; the brand blue globally), `--blue-deep` `#0062CC` (hover), `--blue-soft` `#E5F1FF` (tints/focus), `--gray` `#E9E9EB` (user bubbles), flat white `--bg`, `--poll-fill`/`--poll-ink` (iOS 26 Messages poll orange). The bubbles are the only color on the page — no gradients, no drop shadows, no hover states on bubbles, no second accent beyond the poll orange.

**Dark mode** — an iOS-style flip switch in the nav toggles `html.dark`, which overrides the tokens to real Messages dark (true-black `--bg`, `#3B3B3D` user bubbles, `#0A84FF` iOS dark system blue, dark poll orange). All theme-dependent colors live in tokens on `:root`/`html.dark` — never hardcode a color in a rule; add a token. The choice persists in `localStorage('cued-theme')` and is applied pre-paint by the head script to avoid a white flash.

**Desktop scrollytelling (≥768px, motion OK)** — the hero lands on a serif headline ("Meet cued. made for your college life." + subhead "Your personal fitness coach — no app, just texts [Messages icon] / Your cue to lock in." + a "Join the waitlist" CTA (`#heroCtaTop`, source `hero`), `.hero-head`), the Campanile fully drawn at left, and a flat vector iPhone frame (`.cv-phone`: evenodd bezel ring, island, side buttons in `--cv-bezel`; a Messages-style header with the cue-ball avatar and "cued" on the screen paper in `.cv-under`) peeking up from the bottom edge (offset `PEEK` × height, pushed down further if the headline block would collide) with the first bubble already on its screen; the remaining bubbles pop on a timeline at the first scroll gesture or after ~2s idle. The headline inks in word by word on load (JS wraps words in `.w`, staggered `transition-delay`, `.inked` after fonts) and the subhead carries an inline Messages icon. Ten app icons (`images/app-icons/`: MyFitnessPal, MacroFactor ×2, Hevy, MyNetDiary, Reminders, Notes, pen-and-paper, Google Calendar, Canvas) are scattered around the headline and phone from the first frame like stickers (`SLOTS`, tilted, gently bobbing, still). The hero thread itself is what's on the phone: the driver scales `#hero .shell` about its bottom-right corner and parks it inside the drawn frame (no copy of the bubbles). The hero's first `--cv-len` (300vh) of scroll is the scrubbed convergence sequence, a pure function of progress `p` written once per frame from one IntersectionObserver-gated rAF loop, transform + opacity only: headline drifts up and out (p .05–.18) → phone rises from its peek to center (.08–.30) while the icons glide from their slots onto the orbit ellipse (.08–.28) and the orbit starts turning (angle accumulates only while p is in .08–.24, ~40s per revolution) → icons stream into the phone in index order (.32–.56) → absorb pulse + faint blue screen wash (.56–.62) → the phone, its thread, and the Campanile fade out (.62–.70) → the statement (`.hero-say`, one sentence in the site's voice with the replaced apps inline as tile clusters, `text-wrap:balance`) fades up (.66–.74) and inks in word by word (.70–.98; JS wraps words and clusters in `.sw`, toggles `.on`; un-inked icons are grayscale). After `p = 1` the hero holds 20vh on the inked statement (set a little below center), then the stage releases and the tour starts on its own screen after a short breath — the statement and the first conversation never share a frame. A load or fling already past the hero settles it instantly. No icon labels in the scatter; Strava is deliberately absent (§7 "keep strava"). The floating waitlist pill doubles as the hero CTA — it surfaces bottom-center once the bubbles have settled and the sequence has played out (`cvPast`); the scroll cue is flow-only (the peeking phone is the cue in the pin).

Below the hero, the tour is a plain vertical flow (`.sec--pin` is now just a hook name): no sticky stages, no pinning, no push-up — a Messages-width column (`.sec--pin .shell` ≤760px, ~20px bubbles, 72% max bubble width), small inline serif headers (`.hdr-flow`, ~26px; mid-thread headers carry a top margin), bubbles fading in via IntersectionObserver as they scroll into view, section rhythm from `.sec--pin{padding-top}`. The poll auto-picks and the checklist logs itself on intersection. The `.sec-h` pinned-header markup is still in the DOM but hidden.

**Mobile (<768px, any motion preference)** — the same flow tour; only sizing differs (tight shell, 17px bubble text — real Messages size, 27px inline headers, compact close section). The hero is a static scene, not a scrub (`MOBILE HERO SCENE` block at the end of the sheet): the stage becomes a three-row grid — headline + subhead (the in-flow `.hero-ctas` row is hidden; the mobile CTA is a full-width "Join the waitlist" button pinned to the bottom of the screen, `.m-cta` / `#heroCta`, source `hero`, over a short page-color fade, visible from the first frame through the tour and yielding once the close section is in view), then one cell where the faint Campanile, the phone paper (`.cv-under`), the thread (`.shell`, absolutely placed on the phone's screen between header and composer at 13.5px) and the bezel + six sticker icons (`.cv`, fixed `nth-child` slots, 3/5/6/8 hidden) overlap, then the statement at a smaller size. Bubbles pop in on the screen via the hero timeline (transform killed). The nav's dark-mode toggle and "get started" are hidden on mobile; the floating pill and scroll cue are desktop-only (the pinned bar replaces them). A notification banner (`.notif`, motion only — iOS-style top banner on mobile, macOS-style top-right card on desktop) nudges the reader to scroll once they've dwelt on the hero ~2.6s past the hero CTA beat; the dwell is a watcher, not a one-shot — leaving the hero resets it, returning re-arms it — and it fires at most once, never after a waitlist CTA touch. It auto-dismisses after ~6.4s, and on tap scrolls to the first section.

**`prefers-reduced-motion` (any width)** — on desktop the hero joins the flow (no sticky, no convergence: headline in flow above the drawing band, then the bubbles, then the inked statement); on phones it's the same static scene as motion-OK mobile; every transition is off. It keeps the width-driven sizing (desktop shell and bubble scale ≥768px, mobile sizing below) — reduced motion changes how the page moves, never how wide it is. Windows "Animation effects: off" reports this query, so a real share of desktop visitors land here; never let it collapse into a phone column. Mode is switched live on media-query change in JS.

**No scroll snap** — a mandatory section snap was tried (in the earlier pinned-tour design) and it traps mouse-wheel readers (nearly every Windows visitor). Verify wheel scrolling (100px notches) and reduced-motion at desktop widths in headless Chromium before shipping scroll-machinery changes.

**Close (`#signup`)** — the statement's twin: one serif line (`.close-say`, rides `.say`) "your cue to lock in." that inks in word by word on intersection, a small gray subline "nothing to download. ready when you are." (`.close-sub`) (JS wraps words in `.sw`, staggered timers; reduced motion renders inked), then the pill CTA (`#closeCta`, source `close`). No bubble. Full-height centered on desktop, compact with a full-width button on mobile.

**Waitlist (the sign-up chat)** — every CTA calls `window.openWaitlist(source)`, which opens a Messages-style card (`.co-*` rules at the end of the sheet; tokens mapped from the page's so dark mode is free) running the same conversational sign-up as the legacy pages' `legacy/js/signup.js`, tightened 2026-09-19 to be minimal and quick: nine steps, one lowercase bubble each in the coach's texting voice, ~320ms typing pill. The composer (field + send arrow) is the same slim row on every step; questions with fixed answers are answered from a list bubble cued sends right after the question (`.co-msg.co-opts`: one gray received bubble, rows stacked with hairlines, a ring at the right that fills blue with a check — the tour poll's ring in the thread's palette; no pills, nothing scrolls sideways, every option visible). A single-select row sends itself; multi-select rows toggle, the read-only field mirrors the running answer, the arrow sends. The bubble then locks (`.done`: picks stay checked, the rest dim) and the answer follows as the reader's blue bubble. No grids, no chips, no confirm buttons. Only name (asked as "what's your full name?"; the coach greets by first name), age and phone are typed (the phone formats itself as `(510) 555-1234` and must be a 10-digit US number before it's accepted). Consent is cued's fine-print bubble (`.co-msg.fine`, terms + privacy links inline) answered with the one chip on offer, "i agree", which sends as the reader's bubble. A 2px blue hairline under the header (`.co-progress`) fills a step at a time; "Delivered" (`.co-meta`) sits under the reader's latest bubble; earlier bubbles fade out under the header (mask) instead of clipping. It is literally the reader's phone, so their sends are blue on the right and Cued's replies gray on the left — the one place the page's Cued-is-blue convention flips. The sheet is frosted glass (`--co-glass`, translucent over a 28px backdrop blur with a hairline rim; inputs/chips sit on `--co-field`, also translucent), so its bubble tails are NOT the page's two-pseudo-element carve (a card-colored carve would sit as an opaque notch on glass): one color extension per bubble, shaped by a `mask` that keeps the in-bubble part plus the curved tip. Sizing never needs a scroll to see the whole thing: desktop is a fixed card `min(560px, 100% - 48px)`; under 768px it's a bottom sheet at `calc(100% - 40px)` of an overlay whose height/top the script sets from `window.visualViewport` while open, so an open keyboard shrinks the sheet instead of covering the compose row (verified at 320×568 up to 412×915 and a 390×430 keyboard-sized viewport). On consent it POSTs `{ name, phone, email: null, source, ts, timezone, active: false, status: 'waitlist', age, gender, goal: [...], biggest_obstacle, experience, equipment, sms_consent: true }` to the Railway `/waitlist` endpoint (backend PR #78, 2026-09-19: the profile lands on the pending row, the Photon iMessage line is provisioned, and `imessage_link` comes back). The success screen offers "Text me on iMessage" (opens Messages pre-addressed with "hey cued"; the backend answers a pending user with one holding line and never coaches them until an admin activates) and "I don't have an iPhone" (`POST /signup/channel { phone, channel: 'sms' }`). No link → "I'll text you the second your spot opens." Re-opening the card resumes the chat where it was left. Never run the flow against the real backend in tests — mock both routes in Playwright (`.context/` has the runner).

**Bubble anatomy** — tails only on the last bubble of a run, built from two pseudo-elements (color extension + page-white carve); both must be at least as tall as the corner radius or the tail detaches. The poll's width is matched to the widest sibling bubble by JS. Every auto-play reveal (hero and tour, motion OK) gets a ~500ms three-dot typing lead-in: a JS-injected `.typing` pill per thread, absolutely positioned just under the last revealed bubble on the incoming bubble's side (blue for Cued, gray for the user), lifting the thread by its height while it shows; the arriving bubble replaces it. The hero's first pop after a scroll start skips it (no room before the reveal).
